# Allied Nippon — лендинг

Одностраничник на чистом HTML/CSS/JS. Видео на фоне перематывается вместе со скроллом:
позиция страницы напрямую задаёт кадр, назад скроллишь — видео отматывается назад.

## Запуск

```bash
python3 serve.py        # http://127.0.0.1:8777
```

Файл `index.html` можно открыть и напрямую, но лучше через сервер. Встроенный
`python3 -m http.server` не подойдёт: он не отвечает на Range-запросы, а без них
Chrome не начинает проигрывать mp4 — видео зависает в состоянии `stalled`.

## Файлы

```
index.html              разметка, шесть секций
styles.css              стили, тёмная тема, фирменный красный #e01b22
main.js                 скраб видео, прогресс-бар, скроллспай, мобильное меню
serve.py                локальный сервер с поддержкой Range
assets/video/
  hero-scrub.mp4        видео для перемотки
  hero-poster.jpg       первый кадр — постер и запасной вариант
assets/img/             логотипы с allied-nippon.com
```

## Как работает перемотка

`main.js` считает прогресс страницы (`scrollY` / максимальный скролл), умножает на
длительность ролика и подтягивает `currentTime` к этому значению через `requestAnimationFrame`
с коэффициентом `0.14` — отсюда ощущение инерции. Уменьшишь коэффициент — кадр
станет «тяжелее» и будет догонять скролл медленнее.

Чтобы перемотка не дёргалась, видео перекодировано так, что каждый кадр опорный:

```bash
ffmpeg -i original.mp4 -an \
  -vf "scale=1280:-2,format=yuv420p" \
  -c:v libx264 -preset slow -crf 26 \
  -g 1 -keyint_min 1 -sc_threshold 0 -x264-params "no-scenecut=1" \
  -movflags +faststart assets/video/hero-scrub.mp4
```

Без `-g 1` браузер при каждом seek отматывается к ближайшему ключевому кадру и
доигрывает остальное — на скролле это выглядит как рывки. Файл при этом весит
3.4 МБ против 4.6 МБ у исходника, потому что звук выброшен, а битрейт сжат.

При `prefers-reduced-motion: reduce` скрипт снимает `src` с видео и оставляет постер.

## Скролл-снап

`scroll-snap-type: y mandatory` — одно движение переводит на секцию целиком,
остановиться между ними нельзя.

У жёсткого снапа есть известная ловушка: секцию выше экрана браузер тянет обратно
к началу, и её низ прочитать невозможно. Лечится второй точкой притяжения.
`main.js` замеряет каждую секцию и тем, что не поместились, дописывает в конец
маркер `.snap-end` со `scroll-snap-align: end` — он притягивает нижний край секции
к нижнему краю экрана. Такая секция проходится за два движения вместо одного.

Порог `SNAP_SLACK` в `main.js` намеренно маленький (2px, только на округление высот).
Если его поднять, секции с небольшим перебором останутся без нижней точки, и этот
перебор станет недостижимым — между соседними точками появится дыра больше экрана.

Замер повторяется на `resize` и после `document.fonts.ready`: загрузка Inter меняет
высоты.

На экранах уже 700px снап выключен целиком — там секции длиннее и притяжение начинает
драться с инерцией тача. При `prefers-reduced-motion: reduce` тоже выключен.

Чтобы секции вообще помещались в экран, вертикальные отступы и кегли заголовков
заданы через `clamp` с единицами `vh` и сжимаются вместе с высотой окна. На 1512×850
и выше в экран укладываются все шесть, ниже — маркеры получают одна-две секции.
